# 🎂 Decorator Design Pattern

The **Decorator Design Pattern** lets you **add behavior or responsibilities to objects 
dynamically** without modifying their base class. Think of building a cake — you start with a **plain sponge cake** and add **layers** like chocolate, fruits, or sprinkles 
**without changing the original cake class**.


---

## 🏆 **Key Advantages**

| **Feature** | **Benefit** |
|-------------|-------------|
| Dynamic Behavior 🎭 | Add or remove responsibilities at runtime. |
| Open/Closed Principle 📐 | Extend functionality without altering existing code. |
| High Flexibility 🔄 | Compose different combinations easily. |
| Clean Code 🧹 | Keeps core classes simple and focused. |

---

## 📌 **When to Use**
- Adding features **dynamically** without bloating the base class.
- UI components (e.g., scroll bars, borders, themes).
- Extending frameworks or libraries **without touching original code**.
- Building layered objects like **cakes, drinks, or notifications**.
